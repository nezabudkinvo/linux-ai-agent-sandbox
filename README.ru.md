# linux-ai-agent-sandbox

[English](README.md)

ИИ развивается очень быстро, и многие уже привыкли доверять агентам вроде Claude
Code или Codex все содержимое своего компьютера. Вместе с удобством растет и
риск: агент может прочитать или использовать файлы, которые вы хотели бы
оставить при себе, в том числе конфиденциальные. Защита немного усложняет работу
с агентом, но таких инструментов со временем будет становиться только больше.

Когда агент и пользователь работают под одной учетной записью, система почти не
может их различить. Поэтому самый простой надежный способ защитить данные, на
уровне самого ядра, - полностью разделить их: завести для агента отдельную
учетную запись. Этот проект помогает настроить такое окружение и дает удобные
команды для управления им.

Первая версия управляется из терминала или из Файлов (Nautilus, файловый
менеджер Ubuntu). Собственное приложение для управления защитой уже есть и
сейчас проходит тестирование у автора.

> Статус: ранняя версия. Проверено на чистых виртуальных машинах Ubuntu 24.04,
> Debian 12 и Arch Linux. Что защищено, а что нет - в [SECURITY.md](SECURITY.md)
> (на английском).

## Коротко

- У агента свой пользователь Linux. Он работает в ваших настоящих папках, но
  только там, где вы разрешили: ядро проверяет каждое обращение к файлу, какой
  бы программой агент ни пользовался.
- Для каждой папки или файла вы выбираете: **открыто** (агент читает и пишет),
  **только чтение** или **закрыто** (агент его даже не видит).
- Сразу после установки агент ничего не видит в домашнем каталоге: вы
  открываете папки проектов, в которых ему работать (`safeai` предложит это в
  первый раз). Или выберите при установке режим relaxed: ваши папки открыты, а
  защищено только то, что не должно утечь или измениться (файлы `.env`, ключи и
  пароли закрыты; настройки и места, откуда запускается код, вроде `~/.bashrc`,
  `~/bin`, `.git`, - только для чтения).
- Ваши собственные `claude`, `codex` и VS Code работают от вас, как раньше.
  Агент запускается только там, где вы попросите: `safeai` открывает терминал
  агента; VS Code тоже можно переключить на агента.
- Все удаляется без следа: `sudo /usr/local/lib/safeai/uninstall.sh`.

Сама команда `safeai` отвечает на английском; на русском - установщик и этот файл.

## Как это выглядит

```
$ safeai close ~/Documents/taxes             # агент это никогда не увидит
$ safeai read ~/bin                          # может запускать, но не менять
$ cd ~/Projects/website && safeai            # терминал агента в этой папке
aiagent$ claude                              # Claude работает от агента
$ safeai ls ~/Projects/website
write   /home/me/Projects/website
closed  .env                        (.env)
read    .vscode/
$ safeai log                                 # куда он пытался попасть и получил отказ
09-28 21:12     2x  open             cat            ~/Documents/taxes/2025.pdf
```

## Установка

```
git clone https://github.com/nezabudkinvo/linux-ai-agent-sandbox
cd linux-ai-agent-sandbox
git checkout v0.1.1     # последний релиз; на GitHub его метка отмечена Verified (подписана)
./install.sh --plan     # сначала посмотреть все изменения; ничего не меняется, без sudo
./install.sh            # вопросы, план, потом sudo ровно на этот план
```

Установщик работает от вас: спрашивает язык (английский или русский), имя
пользователя агента, режим и какие части ставить, и показывает полный план.
Только после вашего согласия он просит sudo, чтобы выполнить этот план и ничего
больше. Сам он ничего не скачивает (недостающие пакеты ставит ваш менеджер
пакетов). Сама программа ставится в `/usr/local` (принадлежит root, поэтому ни ваши программы,
ни агент не могут ее изменить); скачанную копию потом можно удалить.

Проверить результат: `/usr/local/lib/safeai/check.sh` (от себя).

Обновить: `safeai settings`, затем `u` (или `safeai settings update`). Ставится
только более новый релиз, подписанный ключом проекта, который ваша установка
запомнила при установке; перед запуском установщика через sudo команда покажет,
кем подписан релиз и что изменилось, и спросит. Ваши правила и ответы
сохраняются. Вручную, в своей копии: `git fetch --tags && git checkout vX.Y.Z`,
посмотреть изменения, затем `sudo ./install.sh --update`.

Хотите сначала попробовать, не трогая систему? `tests/vm.sh test ubuntu`
запускает все в одноразовой виртуальной машине.

Удалить: `sudo /usr/local/lib/safeai/uninstall.sh` - подробнее в разделе
[Что меняет установщик](#что-меняет-установщик).

## Использование

```
safeai                          терминал от агента в этой папке (предложит ее открыть)
safeai status                   режим и все ваши правила
safeai settings                 настройки в меню: режим, VS Code, Файлы; там r убирает
                                все ваши правила, u ставит новый подписанный релиз (оба спросят)
safeai ls [ПУТЬ]                что агенту можно с каждым файлом здесь
safeai open ПУТЬ...             агент читает и пишет
                                (для настроек и мест, где выполняется код, сначала спросит y/N)
safeai read ПУТЬ...             агент читает, но не меняет
safeai close ПУТЬ...            агент не может ни читать, ни войти
safeai check [--fix]            проверить и починить (идет само каждые 5 минут)
safeai log [ЧАСЫ|all]           отказы агента (если включен журнал)
```

Запустить агента:

```
cd ~/Projects/website
safeai                 # терминал агента (в первый раз спросит, открыть ли эту папку)
claude                 # в нем: Claude от агента (или codex, или любой другой агент)
```

У агента свои копии ИИ-программ и свой вход в аккаунт. Когда вы впервые
наберете `claude` (или `codex`, `gemini`) в терминале агента, он покажет одну
команду, которая поставит программу агенту, без sudo. Программы, поставленные
для всей системы, работают у агента и так. В VS Code ставить ничего не нужно:
расширения приносят программу с собой.

Если агенту нужно то, куда у него нет доступа, он останавливается и просит вас,
с готовой командой (`safeai open ПУТЬ` или `safeai read ПУТЬ`); для секретов -
просит сделать изменение самим. Эти правила ему дает установщик
(`~/.claude/CLAUDE.md` и `~/.codex/AGENTS.md` пользователя агента).

## Подробности

### Режимы

Для всего, что вы не настроили сами (переключается в `safeai settings`):

- `strict` (по умолчанию): агент ничего не видит в домашнем каталоге (даже
  список файлов), пока вы что-то не откроете или не разрешите читать.
- `relaxed`: ваши папки открыты, новые тоже; скрытые настройки и папки программ
  вроде `~/bin` - только для чтения. Удобно, но все, что вы не закрыли (и
  `~/Documents` тоже), агенту открыто.

В обоих режимах:

- закрыто: хранилища ключей (`~/.ssh`, `~/.gnupg`, профили браузеров, связки
  ключей, учетные данные облаков, git и менеджеров пакетов, входы других
  ИИ-инструментов) и каждый файл вида `.env` - с момента появления;
- только для чтения даже в открытых папках, с момента появления (в том числе
  после нового `git init` или `git clone`): весь `.git` ваших репозиториев,
  `.vscode`, `.envrc`, `.claude`, `.codex`, `.mcp.json`. Так агент не подложит
  код, который потом выполните вы или ваши программы. `safeai open` для них
  сначала спрашивает, по умолчанию - нет. Ваши репозитории агент читает
  (`git status`, `log`, `diff`), но не коммитит в них: его изменения
  коммитите вы. В репозитории, который он склонировал или создал сам, он
  коммитит как обычно; свой git там не запускайте (`safeai ls` и
  `safeai status` помечают такие репозитории);
- файлы, которые вы сами сделали личными (права 600/700), остаются личными;
- файлы, которые агент создает в открытых папках, становятся вашими.

Сеть агента не ограничивается: он ходит в сеть по тем же правилам, что и любая
программа в системе (собственные песочницы агентов, например `/sandbox` в Claude
Code, внутри safeai не запускаются: им нужно монтировать файловые системы, а
профиль AppArmor safeai это запрещает). `localhost` у вас общий: сервер разработки, запущенный
агентом, открывается в вашем браузере как обычно, а службы, которые вы держите
локально, доступны ему как любому пользователю машины - закрывайте их паролем.

### VS Code и Файлы

- VS Code, в `safeai settings`: расширения Claude Code и Codex всегда работают
  от агента; закрытую для него папку он не откроет и молча от вас не
  запустится. По умолчанию выключено.
- Файлы (Nautilus): меню по правому клику (open / read-only / close) и значки.
  Установщик предлагает их, если Файлы - ваш проводник по умолчанию; добавить
  позже: поставить `nautilus` и `python3-nautilus` и снова запустить установку.

### Что нужно

Linux с systemd, домашний каталог на файловой системе с ACL (ext4, btrfs, xfs),
Python 3.8+, sudo; apt, dnf или pacman, чтобы доставить недостающие пакеты.

По желанию:

- AppArmor, чтобы файлы `.env` запрещались агенту в момент открытия. В Ubuntu,
  Debian и openSUSE он включен сразу; в Arch его сначала нужно включить (см.
  Arch wiki, "AppArmor") и снова запустить установку. Без него новые `.env`
  закрывает служба сразу после появления.
- auditd для `safeai log`.
- nautilus-python для расширения Файлов.

### Что меняет установщик

- Записывает каждый созданный файл, пользователя, службу и пакет в
  `/var/lib/safeai/manifest` и сохраняет копию каждого существующего файла,
  который меняет.
- Если какой-то шаг не удался, откатывает все, что успел сделать.
- Не трогает сеть, других пользователей, ваши группы и вход в систему.
- `uninstall.sh` возвращает все по этому списку: восстанавливает сохраненные
  файлы, удаляет созданное, убирает записи ACL на ваших файлах и возвращает им
  прежние права, удаляет ваши списки safeai. Спрашивает, удалить ли
  пользователя агента с его домашним каталогом (входы и история чатов),
  поставленные пакеты и скачанную копию; по умолчанию - да. `--yes` без
  вопросов удаляет все, кроме скачанной копии.
  Файлы, которые агент сделал в ваших папках, остаются - они ваши.

Пожалуйста, прочитайте `install.sh`, прежде чем соглашаться с его планом - он
специально короткий.

### Как устроено

- `bin/safeai` - команда; работает от вас и меняет ACL на ваших файлах.
- `libexec/safeai-guard` - небольшая служба root (fanotify): отдает вам новые
  файлы агента, сразу закрывает новые `.env`, применяет режим к новым папкам в
  домашнем каталоге.
- `libexec/safeai-run` - запускает программу от агента с чистым окружением (без
  токенов и сокетов вашего сеанса), внутри профиля AppArmor.
- `libexec/safeai-shell` - оболочка входа агента: все, что он запускает,
  работает внутри профиля.
- `share/apparmor/safeai-agent.in` - профиль: разрешено все, кроме файлов с
  именами секретов вне `/tmp`, монтирования и смены профиля.
- Таймер systemd раз в 5 минут запускает `safeai check --fix`.

### Проверка

`tests/vm.sh test ubuntu [strict|relaxed]` (есть еще `debian` и `arch`)
поднимает одноразовую виртуальную машину (QEMU/KVM, без root), ставит туда эту
копию и запускает проверки. `tests/vm.sh clean ubuntu` ставит, использует и
удаляет safeai, а потом сравнивает машину с тем, какой она была до установки.
